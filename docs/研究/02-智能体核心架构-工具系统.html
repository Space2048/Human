核心架构 · 工具系统（手脚）

一个人不能只靠脑子活着 —— 工具系统是数字人类的"手脚与五官"：看得见、搜得到、做得了。

手脚 视觉 · 搜索 · 执行 2026-08-13

1. 设计思想：LLM 的"化身"（Embodiment）

纯对话式 LLM 是"无实体"的：它只能通过文字与世界互动。而 HUMAN 要给 LLM 一个化身，让它的思维能落到真实世界中。

工具系统包含三个层次，对应人类"感知 → 获取信息 → 改变世界"的能力链：

👀

图像识别眼镜（感知层）

多模态视觉理解：看懂屏幕截图、图片、界面元素，像人一样"看"世界。

🔎

浏览器搜索（信息层）

网页浏览、搜索、抓取信息 —— 数字人类获取"知识"的主要途径。

🛠️

环境自主执行（行动层）

在部署环境中运行命令、读写文件、调用 API —— 真正"动手做事"。

2. 图像识别眼镜：视觉感知

人的第一信息通道是眼睛。数字人类需要一个"眼镜"来感知视觉信息，包括：

  • 屏幕理解：操作系统/网页的界面截图，识别按钮、输入框、弹窗等元素。
  • 图像内容理解：用户发来的图片、网上的图片，"看"出其中的对象、文字、场景。
  • 环境感知：来自摄像头的实时画面（如摄像头截帧），理解物理环境。

技术路径

方案原理优点缺点
纯视觉多模态模型（如 UI-TARS / GPT-4V 类）直接输入截图，模型输出点击/输入等操作坐标跨平台、抗界面改版、无需解析底层 DOM依赖闭源/大模型，成本高
可访问性树 / 伪 HTML（如 Eko、Browser Use）读取 DOM 或 Accessibility Tree 转为文本结构稳定、便宜、精确遇到 Canvas/SVG 等盲区时需要视觉兜底
混合方案（推荐）文本结构为主 + 视觉兜底成本与准确率平衡实现复杂度较高
👁️
关键洞察：视觉不是替代 DOM，而是补充 DOM。能用结构化数据就不浪费视觉，视觉专门解决结构化盲区 —— 这与人眼 + 记忆的协作方式一致。

3. 浏览器搜索：获取外部知识

数字人类需要"上网冲浪"的能力，这与人类查资料、读新闻、逛街是同一件事。核心能力：

  • 搜索引擎调用：关键词搜索 → 摘要列表 → 选择深入阅读。
  • 网页浏览：打开链接、滚动、点击、填表、等待加载。
  • 内容提取：抓取正文、表格、列表，转换为结构化记忆。
  • 证据留痕：截图保存（带哈希校验），形成"我看到过这个"的证明。

工程要点

  • 长时间任务支持：30~50+ 步的多页面流程，需要有检查点（Checkpoint），崩溃可续跑。
  • 上下文预算管理：浏览历史不能全塞进窗口，需按重要性打分保留 5~25 条关键步骤。
  • 自我纠正：检测停滞（重复失败的动作）、循环/垃圾信息防护、三级升级的恢复策略。
  • 失败记忆：记住"这条路走不通"，下次搜索时主动避开。
🧭
参考：Browser Use / Playwright Agent 类项目的实践 —— "一次运行内的记忆"（run-scoped memory）让 Agent 在单个任务内学习导航模式，同时避免跨任务污染。

4. 环境自主执行：动手做事

数字人类必须能在"部署环境"中真正执行，而不能只停留在对话。执行能力分级：

级别能力例子风险
L0 · 只读读取文件、查询状态、网络请求读配置文件、查看系统信息低
L1 · 受控写在沙盒目录内写文件、运行脚本写自己的记忆库、整理笔记中
L2 · 全量执行在授权范围内运行任意命令、调用 API部署服务、操作数据库高

安全护栏（必须内置）

  • 权限隔离：默认最小权限，逐级授权，禁止访问敏感区域（密钥、他人数据）。
  • 操作审计：每一步操作记录日志，可回放、可追溯。
  • 人类叫停：危险操作（删除、付款、外发数据）前必须请求人类确认（Human-in-the-loop）。
  • 回滚能力：文件操作可撤销，状态可恢复。
⚠️
安全不是后置功能，而是架构的一部分：自主性越强，护栏必须越硬。参考 Eko 的"显式人工干预接口"与 VIGIL 的"守门人运行时"设计。

5. 工具反馈闭环

工具系统不是单向的"调用 → 返回"，而是必须形成一个感知-行动-反馈的闭环：

  大脑（思考循环）
     │ ① 产生意图："我想看看今天的新闻"
     ▼
  [搜索工具] ──→ 返回结果（文本）
     │
     ▼
  [打开链接] ──→ 页面加载 ──→ ② 截图（视觉眼镜）
     │                          │
     │                          ▼
     │              [视觉理解] ──→ "页面加载失败，出现错误页"
     ▼                          │
  ③ 重新规划意图               │
     │                          ▼
     └────────── 反馈写入瞬时记忆（环境 + 工具反馈） ──┘

每一次工具调用的结果、错误、异常都要回写到瞬时记忆，成为下一步思考的输入。工具系统与思考循环的接口设计详见 研究 03。

6. 结论与待办

  • ✅ 确定三层次工具模型：视觉眼镜 / 浏览器搜索 / 环境执行。
  • ✅ 确定"结构化优先 + 视觉兜底"的混合感知方案。
  • 📋 待办：工具注册与统一调用协议（Function Calling Schema 设计）。
  • 📋 待办：执行沙盒与权限分级的具体实现方案。
  • 📋 待办：工具调用日志与审计数据结构设计。
