1. 技术设计总原则

理论设计追求"像人"，技术设计追求"可落地、可观测、可演进"。两者之间有三条原则：

  • 先通后优：首版先让整条链路跑通（能活 → 有手 → 有记忆 → 有性格），再逐层优化，不追求一步到位。
  • 可观测优先：思考、记忆、行动都要能回看 —— 没有观测，就无法"教育"它（研究 01 的设计原则）。
  • 层间只走协议：层与层之间通过明确接口往来，保证每层可独立替换（换模型、换向量库、换工具）。
✳
核心取向：这套系统最大的风险不是"技术不会"，而是"不可观测导致无法调试"。所以观测优先是技术设计的首要原则。

2. 技术栈选型

维度选型理由
语言Python 3.12LLM/Agent 生态最成熟；异步支持好，适合事件驱动
LLM 接入LiteLLM（多模型抽象层）一套接口接 OpenAI/Anthropic/本地模型，满足多模型混合
思考引擎自研调度器（asyncio）思考循环是核心本体，不适合用现成框架硬套；异步事件驱动最贴合
向量检索ChromaDB（内嵌式）本地文件化、零部署、支持内存模式，首版最轻
结构化存储SQLite + JSON 文件身份档案、大纲索引、印记用 SQLite；原始记忆用 JSON 文件（可读可查）
嵌入模型BGE-M3 或 text-embedding-3中英文效果平衡，成本低
浏览器自动化Playwright跨浏览器、可截屏、可读可访问性树；配合视觉模型做"眼镜"
工具执行受限 Shell（子进程 + 白名单）第一版不追求完全沙盒，先做权限分级与审计日志
人机接口CLI（Rich）→ 后续 Web（FastAPI + SSE）首版 CLI 最快跑通；SSE 为后续"流式思考"预留
配置Pydantic Settings + YAML身份档案、动机配方、节奏参数全部外置为 YAML，可改可查

│   ├── rag.py                 # 向量检索
│   ├── outline.py             # 大纲索引
│   └── decay.py               # 衰减调度
├── act/                       # 行动层
│   ├── registry.py            # 工具注册表
│   ├── shell.py               # 受限执行

├── observe/                   # 观测层

└── data/                      # 运行时数据（记忆库 / 日志 / 档案）

5. 技术设计要点小结

  • 三原则：先通后优、可观测优先、层间走协议。
  • Python 3.12 + LiteLLM 多模型 + asyncio 自研引擎。
  • ChromaDB（向量）+ SQLite/JSON（结构化）双存。
  • Playwright 做"眼镜+手"，受限 Shell 做"脚"。
  • CLI 首版 → Web(SSE) 演进；配置全部外置 YAML。
