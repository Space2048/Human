核心引擎设计

思考循环是系统的"心脏"。引擎设计解决：它如何跳、每跳做什么、被打断怎么办。

引擎 设计层面 · 技术 2026-08-14

1. 设计目标

核心引擎要满足三个技术目标：

  • 持续心跳：进程常驻，按节奏自驱动运转（呼应研究 08 的五条节奏线）。
  • 可打断：强反馈能插队（呼应研究 07 的反馈路由器），且打断后可恢复主线。
  • 可观测：每一轮思考都留痕，能回放（呼应研究 13 的观测优先原则）。

2. 调度器：心跳机制

调度器是引擎的"心脏起搏器"。它按节奏参数定时触发思考轮次，节奏由状态层（研究 11）提供：

状态层（节奏 · 心境 · 时间）
        │ 当前节奏参数（专注 / 走神 / 静默 / 应激）
        ▼
思考循环调度器 ──tick──▶ 单轮执行器
        │                      │
        ├─ 优先级队列 ◀── 反馈路由器（强反馈插队）
        │
        └─ 心跳日志 → 观测层
节奏触发频率单轮深度
专注块高（密集 tick）完整四步，斟酌充分
走神中（随机 tick）联想式，浅斟酌
静默消化低（稀疏 tick）以印记整理为主
应激即时（插队）跳过检索/斟酌，直出意图

3. 单轮执行器：四步实现

每一轮思考（研究 09 的四步骨架）在技术上是四个有序阶段：

  1. 感知（collect）：从事件队列 + 瞬时记忆取"桌上有什么"。事件入队由接口层和反馈路由器负责。
  2. 检索（retrieve）：调用记忆服务召回相关记忆 + 身份约束 + 心境着色参数（并行可合为一个 Prompt 上下文）。
  3. 斟酌（deliberate）：LLM 推理，结合身份、动机、风险记忆生成判断 —— 这一阶段最"贵"，但决定人格。
  4. 产出（emit）：结构化输出三件套 念头 / 意图 / 印记，分别路由到工作台 / 动机引擎 / 记忆服务。
✳
技术取向：四步不是四次 LLM 调用。首版可合并为一次调用 + 结构化输出（四步是"逻辑阶段"，未必是"网络调用"）。后期再按需拆分。

4. 数据模型：轮次与事件

引擎的观测基础是三个核心数据对象：

对象字段（示意）用途
Eventid · type · payload · 时间戳 · 强度一切输入的统一形态（人类 / 环境 / 工具 / 反馈）
Turnid · 节奏 · 感知摘要 · 检索引用 · 产出三件套 · 消耗一轮思考的完整留痕，可回放
Impression内容 · 来源 Turn · 重要性 · 时间印记，待沉淀进长久记忆

这三个对象都写入观测层日志，且 Turn 引用 Event 与 Impression —— 回放一轮思考，就能看到它被什么触发、想到了什么、记住了什么。

5. 打断与恢复

强反馈打断是引擎必须处理的场景（呼应研究 07）：

  • 打断：反馈路由器把强事件插入优先级队列头部，调度器暂停当前主线，先处理。
  • 上下文保存：被打断的轮次不丢弃，其"未完成意图"挂起（研究 10 的动机滞留）。
  • 恢复：处理完打断事件后，按动机滞留强度决定是回到原主线，还是转入新线。
✳
技术取向：这个"保存-挂起-恢复"机制，技术上就是一个任务栈 + 意图优先级。人被打断后能否回到原事，取决于"这事多重要"——动机引擎提供这个权重。

6. 设计要点小结

  • 调度器按节奏 tick，事件队列支持插队。
  • 单轮四步是逻辑阶段，首版合并为一次调用。
  • Event / Turn / Impression 三个对象支撑完整观测。
  • 打断 = 任务栈挂起，恢复靠动机滞留权重。
