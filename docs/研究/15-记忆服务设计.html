记忆服务设计

理论三层记忆（RAG / 大纲 / 模糊）落成技术：谁存、怎么存、何时忘、如何想起。

记忆 设计层面 · 技术 2026-08-14

1. 三层存储的技术映射

研究 04 的理论三层，在技术上对应三种存储：

理论层技术实现存储介质写入者
RAG 库（事实）向量库 + 全文索引ChromaDB印记沉淀（引擎）
大纲索引（结构）关系表 / JSON 图SQLite深度整理（研究 12）
数据模糊（遗忘）衰减字段 + 调度任务SQLite + Chroma 元数据衰减调度器
✳
技术取向：向量库只管"检索"，不负责"记忆"。真正的"记忆感"来自大纲索引的结构化与衰减调度的遗忘——这两层在 SQLite 里，可读可改可审计。

2. 记忆写入流程

一条经历从"发生"到"成为记忆"，经过三个环节：

引擎产出 印记（Impression）
        │
        ▼
① 重要性评分 ── LLM 打分 + 规则保底（研究 07 的"规则+判断"混合）
        │
        ▼
② 双写 ── 正文进 Chroma（可检索）
        │     元数据进 SQLite（时间 · 来源 · 重要性 · 情绪标签）
        │
        ▼
③ 等待深度整理 ── 夜间批量：重排进大纲 / 低价值衰减 / 模式沉淀为印记

3. 记忆读取流程

检索（研究 09 的第二步）不是"查一次向量"，而是三次调用混合：

  1. 向量召回：语义相似的前 K 条（Chroma）。
  2. 结构召回：大纲索引里与当前主题相关的关系/脉络（SQLite）。
  3. 着色：身份偏好过滤 + 心境加权（研究 11）—— 低落时更容易想起失败经历。

三次结果合并成"这轮思考带着什么记忆来"的上下文。

✳
技术取向：着色（第 3 步）是"拟真记忆"与"企业 RAG"的分野所在 —— 纯向量检索是精确的，加了人格过滤与心境加权，才像"一个人想起的事"。

4. 衰减与遗忘

数据模糊层（遗忘）由衰减调度器实现，按主观时间轴（研究 11）运行：

  • 重要性衰减：每条记忆有 salience 字段，随"距上次想起的时长"衰减（模拟"久未想起会淡忘"）。
  • 混淆合并：相似记忆在深度整理时合并，生成"模糊化"的概括（研究 04 的相似混淆）。
  • 废弃清理：salience 低于阈值且无引用的记忆进入"遗忘区"，从活跃检索中剔除。
  • 可追溯：遗忘不物理删除，标记 forgotten —— 教育/回滚时可找回（呼应"可重置"约束）。

5. 大纲索引：记忆的结构骨架

大纲索引是让记忆"像人"的第二关键（第一是着色）。它维护几类结构：

结构内容示例
人物关系谁 · 关系 · 事件锚点"小林 · 好友 · 一起改过 bug"
事件主线连续事件的因果链"发布 → 用户反馈 → 反思 → 改进"
知识框架学到的概念与联系"RAG = 检索 + 生成"
自我认知对"我是谁"的归纳"我 · 遇到反复失败会怀疑自己"

大纲由深度整理（研究 12）从散碎记忆中归纳生成，同时被检索时用于"结构召回"。

6. 设计要点小结

  • 向量库只做检索，记忆感来自大纲 + 衰减。
  • 写入 = 评分 → 双写 → 等整理。
  • 读取 = 向量 + 结构 + 着色三路合并。
  • 遗忘 = 衰减 → 合并 → 标记，不物理删除。
  • 大纲索引是"像人"的结构骨架。
