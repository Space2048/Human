前端展示功能设计

这个系统的独特之处不是"能聊天"，而是"能看到一个大脑在想什么"。前端就是那扇窗。

前端 细化设计 2026-08-14

1. 定位：不是聊天框，是"大脑之窗"

普通 Agent 的前端是聊天窗口。HUMAN 的前端必须是观察窗——因为系统的首要约束是"可观测"（研究 13），教育（研究 05）的前提就是能看到它在想什么、记住什么、为什么这么做。

所以前端有两类角色：

  • 交流者：与数字人类对话、教导、提问 —— 它"说"的入口。
  • 监护人：查看它的内心独白、记忆、心境、行动轨迹 —— 观察并教育。
✳
设计取向：前端展示的不是"答案"，而是过程。观察一个念头如何变成行动，比看到结果更能让人理解（并教育）这个数字人类。

2. 界面分区

前端整体划分为五大面板，对应系统的核心结构：

面板展示内容数据来源监护人价值
对话区对外言语（与人类的交流）表达层（研究 12）与它对话、教导它
思考流内心独白、念头、意图实时滚动Turn 记录（研究 14）看它"到底在想什么"
状态栏心境三轴、当前节奏、时间状态管理器（研究 11）理解它"此刻状态如何"
记忆库可检索的印记、大纲、遗忘区记忆服务（研究 15）回看它"记得什么、忘了什么"
行动日志工具调用、反馈事件、审计观测层（研究 13/16）回放它"做过什么、为何如此"

3. 核心交互：实时观察（SSE 流）

前端的灵魂是实时——思考不能等轮询，要用流式推送：

  • 思考流实时滚动：每一轮 Turn 产出即推送到前端（SSE），像看它的脑电图。
  • 状态栏实时刷新：心境变化、节奏切换即时可见（如"专注块→走神"的切换）。
  • 行动日志即时追加：工具被调用时，调用参数与结果摘要立刻出现。
  • 打断可视化：强反馈打断发生时，界面上能看出"它被什么打断了"。
✳
技术取向：SSE（Server-Sent Events）单向推送足够覆盖全部场景，比 WebSocket 简单可靠。只有未来需要"远程操控"才升级 WebSocket。

4. 特殊展示：记忆的可视化

记忆库面板是"监护人"最有价值的部分，做三档展示：

🔍

检索

输入关键词/语义，检索 RAG 库，看它"此刻会想起什么"。

🗂

大纲图

人物关系、事件主线、知识框架的图化展示，看它的"认知结构"。

🌫

遗忘区

被衰减标记的记忆，展示"它正在忘记什么"——监护人可决定是否找回。

5. 教育与干预入口

前端不仅是观察窗，也是教育的入口（研究 05）：

  • 直接对话：像和人说话一样教导、纠正、表扬。
  • 危险操作确认：工具的高危动作弹出确认框（研究 16 的 Human-in-the-loop）。
  • 记忆干预：查看/修改/找回记忆（可重置约束的界面化）。
  • 档案查看：身份档案、动机配方、节奏参数的可视化与微调。

6. 设计要点小结

  • 前端 = 大脑之窗，观察过程比看结果更重要。
  • 五大面板：对话 / 思考流 / 状态 / 记忆 / 行动日志。
  • SSE 流式推送支撑实时观察。
  • 记忆库三档展示：检索 / 大纲图 / 遗忘区。
  • 教育入口内置于前端：对话、确认、干预、档案。
